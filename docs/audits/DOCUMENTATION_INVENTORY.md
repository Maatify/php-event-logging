# Documentation Inventory

> This inventory reflects the current tracked documentation tree. Documents retained by the Content Preservation Audit remain listed until their current, future, Owner, or unique information has a current authoritative home.

The current consumer surface is domain-specific: six Recorders provide the write entry points, the
five non-authoritative domains fail open at their Recorder boundaries with an optional PSR-3 fallback,
and AuthoritativeAudit remains fail closed. Read consumers have both protected primitive cursor APIs
and separate domain-owned Admin Query offset APIs; examples 09 and 10 demonstrate Admin Query while
example 11 demonstrates the protected primitive cursor path. Integration guides and domain READMEs
describe host-provided wiring, current metadata/path-safety boundaries, and the distinction between
Recorder coordination and domain-specific Policy responsibilities.

Current persistence remains MySQL-only with domain-isolated storage. Reporting/dashboard,
archiving/retention, and outbox-consumer work remain deferred, with future archiving limited to the
approved MySQL-to-MySQL Mode B scope. Host presentation and reporting remain host-owned, while
package-owned domain-scoped Phase 5 contracts require separate Owner approval.

The active pre-RC consolidation phase now also requires a repository-wide Markdown rationalization review. Completed roadmaps, audits, blueprints, review reports, and execution-history documents are not automatically permanent documentation. Each package-owned Markdown file must be content-audited and classified for retention, consolidation, deletion-as-history, or genuinely deferred/future value. Git/PR history is the normal source for execution chronology; the surviving documentation set should concentrate current decisions, architecture, domain purpose, interaction/usage, integration boundaries, and approved future scope.
